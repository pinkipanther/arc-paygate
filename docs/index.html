How it works

Four steps, one transaction

The server never holds keys and never sees a payment off-chain.

01402 with a quote

The server answers with chain id, contract, resource id, price and a signing nonce.

02Client verifies on-chain

It re-reads quote(id) itself, refuses if the numbers differ, and caps its spend.

03Pay in native USDC

pay(id, minWindow) with value = price. Reverts if the seller changed the deal.

04Sign, then read

An EIP-191 signature bound to chain, contract and id proves the address. hasAccess gates the response.

On-chain ledger

Every payment, public

Read straight from Paid events on the contract.

Three lines to buy access

The reference client treats the 402 body as untrusted and builds the payment from the contract itself.
